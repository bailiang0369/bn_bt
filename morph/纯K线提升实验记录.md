# 纯 K 线 3 分钟方向预测：14 轮实验记录

> 目标：在**只用 K 线**（无订单簿、无跨市场）的前提下，提升 3 分钟后方向预测的
> topK 准确率，使纯 K 线腿在与订单簿融合时不拖后腿。
> 记录时间：2026-11-05（第 1~14 轮）。第 1~11 轮 commit `0d6e2d2`/`379ffb7`；
> 第 12~14 轮见 §5 的 kernel 索引。

---

## 1. 数据（已重新生产，不再用旧 dataset）

| 项 | 值 |
|---|---|
| Kaggle dataset | `byh850515/btcusdt-1m-full-2020`（private） |
| 文件 | `btcusdt_1m_full.parquet`，79.1 MB |
| 行数 / 范围 | 3,592,800 行，2020-01-01 00:01 ~ 2026-11-01 00:00（UTC，Int64 ms） |
| 列 | `close_time, open, high, low, close, volume, taker_buy_volume, count` |
| 来源 | Binance Vision `futures/um/monthly/klines`（**U 本位合约**），复用 `bn_hisdata/binance_vision/download_binance_vision.py` |
| 生产 kernel | `byh850515/btcusdt-1m-full-2020-dataset-maker` → `morph/make_full_dataset.py` |

**作废的旧数据源**：`eth-btc-1m-2020`（只有 OHLC，无量能）、`crypto-eth-btc-data`（很早的旧 dataset）。
**CVD 口径**：`2 * taker_buy_volume - volume`，其中 `taker_buy_volume` 是**合约（um）主动买量**，不是现货。

## 2. 评估协议（所有轮次统一，跨轮可比的前提）

- 切分：`VAL_START=1777704120000`（≈2026-05-02）、`TEST_START=1784298120000`（≈2026-07-17）、
  `OB_END=1792540620000`（≈2026-10-21，为与订单簿对齐而截断）。
- test：**96 天 / n=137,373 根 1m**，基准（涨占比）= **0.4925**。
- 泄露防护：train/val 尾部各剔除 `h` 根（标签不跨切分边界）。
- 指标：
  - `static`：val 均值方差 z-score 后，取 `|z|` 最大的 `K = 15 × 天数 = 1440` 个样本，准确率；
  - `按天`：每天取 15 个，仅统计完整交易日（1m `min_bars=1200`）；
  - `AUC`：排序质量，**唯一能判断"是否真的加了信息"的指标**；
  - `窗口4`：test 切 4 段各算 topK，报均值 ± sd。
- **噪声地板（第二轮实测）**：seed 间 sd = **0.47pt**，窗口间 sd = **2.9pt**。
  因此同一 test 上 **< 1pt 的差异不可区分**，必须看 4 窗口是否同向、AUC 是否变化。

## 3. 十四轮结论（全部同一口径）

| 轮 | 试了什么 | 结果 | 判定 |
|---|---|---|---|
| 1 | 3m 重采样 / 符号累加 / 形态子集 / 堆叠 | 3m 掉 5pt；符号累加 static 0.6014 vs 0.6069；堆叠更差 | 全部无效 |
| 2 | 噪声基线 / 标签净化(5,10bps) / 形态+符号 | 净化越好越差，10bps 时 AUC 崩到 0.4993 | 无效 |
| 3 | 8seed / 软加权 / h分数相加 / 多样性 bagging | s8 0.6076、div 0.6097，与 0.6125 不可分 | 无效 |
| 4 | 评估端中心偏移 mu + 单边/对称 | val +1.04pt → test −0.69pt（过拟合）；test 内 oracle 仅 0.6160 | 无空间 |
| 5 | 3m 基础 K 线 LGB + 1D CNN(px/st/vol/cvd) | lgb3m 0.5583、cnn1m 0.5458；**corr(LGB,CNN)=0.198** | 单腿弱，但互补 |
| 6 | CNN 加实体/影线 8 通道 + 权重扫描 | cnn2 0.5382；LGB+0.1cnn → static 0.6167 | 有微弱迹象 |
| 7 | 回归目标（学幅度）/ 时间衰减权重 | reg AUC 0.5165、decay 0.5251（均低于 0.5269） | 无效 |
| 8 | 形态窗口聚类(64簇) + 簇胜率前向编码 | **AUC 完全不变 0.5269**；static 0.5882 | 无效（信息早被覆盖） |
| 9 | **多 horizon 一致性集成**（h=1,2,3,5,10 等权 z 平均） | **static 0.6174 / AUC 0.5277 / 4 窗口 4/4 全升** | **首个真提升** |
| 10 | 剔除 19 个量能特征 + CNN 去 vol 通道 | 44 特征 0.5993（−1.8pt，但 AUC 不变）；**CNN 去 vol：0.5382→0.5514** | 量能保留；CNN 去 vol 正确 |
| 11 | 定稿：多 horizon + 无 vol CNN 加权融合 | **static 0.6264(w=0.25) / 0.6194(w=0.2)，AUC 0.5285，按天 0.5937** | **定稿** |
| 12 | **VP 量价分布 15 列**（POC 距离/价值区间位置/宽度/上下方量比/VWAP 偏离）× 3 窗口 | 63+VP：static 0.6181、AUC 0.5280、按天 0.5846、4 窗口 2/4 升；VP 单独 AUC 0.5209 | 无效（信息已被覆盖） |
| 13 | 每 horizon seed 2→5；CNN 窗口 60→120、5→10 epoch、+CVD 斜率/加速度（7→9 通道） | lgb5s：static 0.6181 / AUC 0.5279 / 按天 0.5888 / 4 窗口 0.6150±0.0423；cnn9 AUC **0.5231**（cnn7 0.5237）；融合 w=0.25 → static 0.6257 / AUC 0.5285 / 按天 0.5895 / 4 窗口 0.6106 | seed 有效但很小；CNN 加长无效；总体打平 |
| 14 | **只把 seed 加到 5**，CNN 保持第 11 轮 7 通道/60 窗口/5 epoch（隔离 seed 增益） | w=0.20：**static 0.6250 / AUC 0.5285 / 按天 0.5979 / 4 窗口 0.6052±0.0234**；w=0.25：0.6243 / 0.5286 / 0.5965 / 0.6046±0.0329 | **新定稿**（AUC 不变，但方差更小、按天最高） |

### 关键判读

- 第 1~8 轮 AUC **锁死 0.5269**：无论换特征、加 CNN、改损失、加形态编码，排序信息都没变。
  这比 topK 数字可靠得多——topK 在 3pt 噪声里可以随便涨跌 1~2pt。
- 第 9 轮 AUC 首次变动（0.5277），且 4/4 窗口同向提升，才认定是真信号。
- 第 11 轮 AUC 随 CNN 权重**单调**升到 0.5285，按天 topK 单调升到 0.5937，同时窗口 sd
  从 0.0473 降到 0.0260 —— 三个独立指标同向，才算确认。
- 第 12 轮 VP **没通过**：AUC 0.5277 → 0.5280（噪声内），4 窗口只 2/4 同向，窗口 sd 反而
  从 0.0473 涨到 0.0564。原因看两点就够：
  - VP 单特征 AUC 全部只有 0.512~0.515（距离类还是**反向**：价在 POC/VWAP 上方 → 略偏跌，
    1-0.4872=0.5128），而 `k_boll_60` 这类已有特征本来就吃满这部分均值回复；
  - 78 个特征里 VP 的 gain 排名 22~68，LGB 基本不用它。
  这说明 VP 不是"没信息"，而是"信息早被 63 列里的位置/布林/量比覆盖"——和第八轮形态聚类的
  结论一模一样。
- **流程教训**：第 12 轮第一次跑出 static 0.9479 / AUC 0.7658，是 VP 锚点用到了未来 bar
  （见踩坑 7）。凡是新特征先跑泄露自检（`kline_vp.vp_leak_check`），再谈收益。
- 第 13/14 轮把"seed 2→5"和"CNN 加长"拆开看，结论很干净：
  - **seed 2→5 不改 AUC**（0.5277→0.5279，CNN 融合后 0.5285→0.5285），即没有新信息，
    只是把估计方差压小：base 腿按天 0.5818→0.5888、4 窗口 sd 0.0473→0.0423，
    融合后按天 0.5937→0.5979、sd 0.0260→0.0234。属于"无损稳健化"，不是提升。
  - **CNN 加长全部无效**：窗口 60→120 + 5→10 epoch + CVD 斜率/加速度，AUC 0.5237→0.5231
    （还退了一点），单独 static 0.5514→0.5472。CNN 的信息量被自己的容量卡住，
    加长窗口只是喂更多噪声。
  - 因此第 14 轮（5 seed + 原 CNN7）在 static / 按天 / 4 窗口 / sd 四项都不低于第 11 轮，
    且 AUC 相同 → 定为新定稿；但**不能声称这 0.5pt 是提升**，它落在噪声地板内。

## 4. 定稿配置（第 14 轮，commit 见 §5）

```
特征   : build_features 63 列（动量/波动/量能/形态/时间），1m；**无 VP**
LGB 腿 : h ∈ {1,2,3,5,10} 各一个 LightGBM(binary, 60 轮)
         每个 h 用 seed 42,43,44,45,46；各自对 val 做 z-score 后等权平均 → base
CNN 腿 : 7 通道 px/body/upper/lower/ret1/st/cvd(合约)，无总成交量
         窗口 60 根 1m，1D 膨胀卷积(c1=16,c2=24,c3=24)，5 epoch，2 seed
融合   : score = base + 0.20 × z(cnn)        # 0.25 时 static 略高、0.20 时按天最高
```

| 口径 | 新定稿(5 seed) | 旧定稿(2 seed) | 起点(0.6049) |
|---|---|---|---|
| static 全局 topK | **0.6250**(w=0.20) / 0.6243(w=0.25) | 0.6194 / **0.6264** | +2.0 / +1.9pt |
| 按天 topK | **0.5979** | 0.5937 | — |
| AUC | **0.5285** | 0.5285 | — |
| 4 窗口 | **0.6052±0.0234**(w=0.20) / 0.6046±0.0329(w=0.25) | 0.6038±0.0260 / 0.6026±0.0346 | — |

判据读法：AUC 完全没动 → 没有新信息，只有方差与 topK 分布的小幅重排；四项口径都不差，
所以换配置安全，但对外只能说是"同等效果、更稳"，不能说"又涨了"。

## 6. 踩过的坑（复用前必读）

1. **分类概率不能直接判方向**：`global_topk_eval` 用 `score > 0` 判涨跌，若传入原始概率
   （恒正）等于全猜涨。第 7 轮 `clf` / `clf_decay` 两行数字因此不可比。正确做法：先对 val
   做 z-score 再判符号（`kline_multi.evaluate` 已修正）。
2. **3m 网格不能直接用 K=15/天**：3m 每天 480 根，15 个 = 3.1% 覆盖率，而 1m 是 1.04%。
   第 5 轮已改为把 3m 分数映射回 1m 网格再评估。
3. **`np.roll` 做 horizon 融合会引入未来 bar**：`p1[t]+p1[t+1]+p1[t+2]` 中 `p1[t+1]` 用到了
   t+1 时刻的特征。正确做法是各 horizon 各自在 t 时刻预测，见 `kline_multi.py`。
4. **`resample_3m` 曾硬依赖 `volume`**：换成只有 OHLC 的 dataset 会直接崩。
5. **`load_klines` 曾只 glob 固定文件名**，找不到就联网下载。现在扫 `/kaggle/input/**/*.parquet`
   并按"是否含 volume + 是否覆盖 test 尾部"筛选。
6. **val 上调参不泛化**：第 4 轮 val +1.04pt → test −0.69pt。凡是"在 val 选最优"的结论，
   必须同时报 test 曲线，不能只报 test 最大值。
7. **降采样/锚点特征最容易偷未来**：第 12 轮 VP 直方图每 10 根 bar 才算一次，映射写成了
   `k_of = pos // anchor`，于是 t=10..18 用的是 t=19 的直方图（未来 1~9 根）。
   症状是 static 0.6174→0.9479、AUC 0.5277→0.7658，**好到不真实**。
   正确写法 `k = (t+1)//anchor - 1`（即最后一个 ≤ t 的锚点）。
   凡是"慢变量 + ffill"的特征，一律先跑 `vp_leak_check()`：把 cut 之后的行情随机化，
   cut 之前的特征必须逐位不变。注意 cut 不能取 anchor 整倍数（否则错位锚点落在 cut 之前，
   检查形同虚设，这里也踩过一次）。
8. **AUC 0.77 的 3 分钟方向模型不可能存在**：纯 K 线所有轮次的真实上限就在 AUC 0.528 附近。
   出现明显高于此的数字，先假设是 bug，不要求解释。


## 7. 尚未尝试 / 下一步候选

第 12~14 轮把上一版列的三条候选全部做完了（VP、seed 5、CNN 120/10ep/CVD 斜率），
结论是**纯 K 线在 AUC 0.5285 已经顶到天花板**：没有一条改动让 AUC 动超过 0.0001。
剩下的方向按性价比排序：

- **不要继续在特征堆里找增量**。9 类特征改动（形态聚类、VP、量能剔除、符号累加、3m 网格、
  标签净化、回归目标、时间衰减、horizon 集成）里只有 horizon 集成动过 AUC，
  其余全部锁死。再换特征形态大概率重复这个结果。
- 唯一还有理论空间的是**样本选择**（不改特征、不改标签）：例如只在 val 选出的
  高波动/趋势 regime 上训练或预测；它改的是"哪些样本进 topK"，与 horizon 集成同源，
  AUC 可能仍不变但按天 topK 可能变——必须同时报 4 窗口，防止只是把覆盖率挪走。
- 多 horizon 权重从等权改成 **val 上选的加权**（第 9 轮只测了等权）。风险明确：
  第 4 轮已经证明"val 选参"容易 −0.7pt 级反噬，做的话必须报 val 曲线 + test 曲线。
- CNN 侧不再加长（第 13 轮已证窗口 120/10ep/CVD 斜率全无效）。若还要碰，只能往
  **减容量 + 强正则 + 早停**方向试，目标是把 AUC 0.5237 提到 0.525 以上；
  低于这个门槛的融合权重不会改变最终 AUC。
- 目标重定义（触及概率 / 更长 horizon）——当前明确不做。
- **明确不做**：跨市场、订单簿、总成交量直接入模（除 VP）、在 test 上调任何超参。

> 建议：纯 K 线腿的性价比已经很低（14 轮换来 AUC +0.0016）。要再上台阶只能靠新数据源，
> 纯 K 线侧维持第 14 轮定稿即可。
