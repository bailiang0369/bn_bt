## 1. h10 逐 bar replay（全局阈值）

配置：H=10、tpd=8、payout=0.80、5 seeds、2000 轮、1460 天窗、3 槽位、0 延迟、无去重、2026-01~10。

| 口径 | 单数 | 胜率 | EV@0.8 | 最差月 |
|---|---:|---:|---:|---:|
| 批量逐行命中（回测） | 2243（7.4/天） | 64.33% | +0.158 | — |
| 逐 bar 实际可下 | 1510（5.0/天） | 64.24% | +0.156 | 56.77% |

- 733 单（32.7%）被 3 槽位拒掉；胜率几乎不变，说明被拒单并不更差，是纯容量损失。
- 周末占比 **92.3%**（批量命中口径）；周六独占 87.7%。工作日 10 个月只有 172 次命中，分星期样本 11~37 单，无法据此判断工作日可用。
- 因果扰动审计：每月 12 个时刻、共 120 次，扰动 t 之后 30 根 bar，t 处特征与预测最大差 **0**，120/120 通过。
- 注：本阶段自包含实现得到 batch 64.33%，与旧文档 63.32% 不是同一实现/数据快照；内部对照有效，不作为旧数字复现。

## 2. h10 分星期阈值对照（证伪）

做法：thr 段（目标月之前）按星期各算一条分位阈值，目标仍是 8 单/天；同一批模型、同月，只替换阈值。严格因果，不是日内 top-K。

| 口径 | 可下单数 | 周末占比 | 胜率 | EV@0.8 | 最差月 |
|---|---:|---:|---:|---:|---:|
| global | 1510（5.0/天） | 92.3% | 64.24% | +0.156 | 56.77% |
| weekday | 1949（6.4/天） | 27.5% | **57.26%** | **+0.031** | **48.72%** |

分星期胜率：周一 58.16%、周二 54.32%、周三 53.05%、周四 57.45%、周五 56.29%、周六 60.87%、周日 61.46%。周二/周三已低于 0.8 平衡线 55.56%。

**结论：关闭。** h10 的 alpha 集中在周末低波动 regime；摊平单量会把 EV 打掉 80%，且月度会破平衡线。不是阈值卡死，是工作日分数分布里没有足够多的合格信号。

## 3. h3 周末集中度与阈值诊断

现役 h3 固定阈值 0.05806、time split、test 段逐行分数（`.codebuddy/artifacts/h3gate/h3_gate_pred.parquet`）：

- 触发单 3895，周末占 **88.9%**；工作日 432 单 / 68 天 = **6.4 单/天**，周末 3463 单 / 28 天 = 123.7 单/天。
- 工作日胜率 59.72%，周末 63.24%（与 `实验详录.md` §23 一致）。
- 阈值扫描（诊断，不作为选参依据）：

| 阈值 | test 工作日（单/天，胜率） | val 工作日（单/天，胜率） |
|---|---|---|
| 0.070 | 1.5 / 66.34% | 0.2 / 33.33%（n=12，噪声） |
| 0.065 | 2.7 / 63.78% | 0.5 / 59.26% |
| 0.05806 | 6.4 / 59.72% | 2.5 / 59.56% |
| 0.050 | 20.8 / 57.80% | 14.2 / 57.44% |

调高阈值在 test 上看着提胜率，但 val 完全不支持，且单量更少；**方向错误**。调低阈值才能匀单，且 val/test 同向。

## 4. h3 工作日独立阈值 replay（待 forward 确认，不上线）

**警告（不能跳过）**：val 后半 mixed 只有 56.08%、最差月 53.91% 破线，且工作日实际 6.4 单/天没达到 15 的目标；test 却是 20 单/天。单量分布本身不稳，因此只能作为**影子运行候选**，不能上线，也不能再拿 test 继续调阈值。

## 5. 共同结论

1. h3 与 h10 的 alpha 都集中在周末低波动 regime；"每天均匀出单"不是实现问题，是信号本身没有全天候覆盖。
2. h10 摊平即塌（EV +0.156→+0.031，月破线）；h3 摊平尚有正 EV（+0.131→+0.111），但 val 后半不稳。
3. 调高工作日阈值在两段上都不支持，不要再试；调低是唯一合理方向。
4. 下一步只做影子运行：固定上述 mixed 阈值，接 2026-11 之后的新数据，只记录信号不下单，确认 val 后半的弱势是不是常态。
5. 交易载体/平台与结算规则尚未确定；在此之前不做真实下单模拟。

## 6. 全特征漂移诊断（2026-11-22，负结果）

用户思路：从历史 Kaggle 执行记录定位坏月，把坏月的全部特征与训练参考分布比较（均值/方差/中位数/PSI），做实时特征监控并按漂移调仓。

标签来源：`h10sig / h10sigA / h10sigB / h10sigC` 的历史 kernel 日志逐月胜率。稳健坏月是 **2026-02 与 2026-05**（基线 55.74/57.53%，A 版 52.96/55.44%，B 版 57.19/48.06%）；7 月/10 月只在个别配置下差。

实现：`live_sim/h10_drift_diag.py` + `kk_drift.py`，Kaggle slug `byh850515/h10-feature-drift-diag`（v1 commit `491a27b`，v2 扩展到原始数据 `c5821a1`）。漂移量取月初前 30 天 trailing 窗口 vs 当月训练参考分布，严格因果；与 11 个月胜率做 Spearman + 5000 次置换检验 + BH-FDR。

两轮扫描：

1. **仅 49 个模型特征 × 4 指标**（mean_z / median_z / std_ratio / PSI，196 检验）：原始 p 最小的是 `lg_dow_cos` PSI（rho +0.77，p=0.0084），但 q≈0.989；全部不存活。且该 PSI 只有 ~0.01，是 28/31 天的日历构成差异，不是市场漂移。
2. **扩展到原始数据与衍生量**：在原 14 个数值列上加 `raw_ret1_bps / raw_absret1 / raw_range_bps / raw_um_imb / raw_spot_imb / raw_flow_div / raw_basis_bps / raw_log_um_vol / raw_log_spot_vol / raw_um_count_share`，合计 **73 列 × 4 指标 = 292 检验**。最强候选反而来自原始数据：`spot_low` 的 std_ratio（rho −0.77，p=0.0052，q=0.316），即现货最低价的离散度越大、次月胜率越低；仍过不了 FDR。其余原始量（波动、价差代理、资金流、基差）都没有更强信号。

结论：

- 用户提出的"漂移可能不在 49 列里"是对的，所以扩展到原始数据层；但即便如此，11 个月标签下仍没有任何漂移量能经得起多重比较校正。
- 没被数据采集覆盖的东西（真实盘口深度/价差、资金费率、清算流）本就无法在此诊断中检验，这是数据边界，不是统计结论。
- "冻结少量特征"不是人为限制，而是 11 个月 + 多检验下唯一可能取得功效的做法；全量扫描两轮都反过来证明了这一点。
- 当前不支持上线任何漂移门控。若继续，先解决标签数量（36 个月）或降低检验维度（预登记单一指标），而不是继续在同一份数据上换特征扫。

## 7. 波动分层阈值诊断（2026-11-22，本地 MDE，未推 kernel）

用户要求重新审查代码、不照搬旧总结，找提升工作日单量+准确率的方法。审查发现旧结论里
"分星期阈值摊平失败"用的是**绝对**分位阈值，未测过**按逐 bar 波动分层、每层独立阈值**，
故本地做先行诊断（`morph/volstrat.py`，注入本地 BTC 1m K 线的 60m 波幅，因果）。

两个纠错（旧总结的表述需修正）：
1. 详录 §24/§23 的 `corr(|p−.5|, log vol)=−0.345` 用的是**逐 bar 波动**（|1m收益|/60m波幅）。
   `h3_gate_pred.parquet` 里的 `s_t` 是 **7 天滚动 |r3| 中位数、按构造抹平星期效应**，
   不能当逐 bar 波动用（实测 corr 仅 −0.063，分层边界 [3.49,3.62] 几乎无区分度）。
2. 本地真实 vol60 分层 corr=−0.212（不是 −0.345，因窗口/标的口径不同），方向一致。

结果 A——单量目标**可达**：h3 test tpd20 分层后工作日 **9.8~9.9 单/天**（基线 6.4），
周末占比 86.6%→69.5%；val 后半工作日 15.8 单/天。equal_count≈equal_rate。

结果 B——准确率目标**不可达（本次核心结论）**：
- h3 分层后工作日胜率 test 57.2~57.4%、val 后半 53.4%（破 0.8 平衡线 55.56%）；整体 62% 是周末 65% 补账。
- 决定性证据：**oracle 上界**（对工作日 |p−.5| 排序取 top-N，非因果、仅诊断）——h3 工作日
  top10/天 56.32%、top12/天 57.60%；最高置信档 |p−.5|≥0.05 也仅 57.80%。
  h10（2026-09 单月）同构：命中 145 单中工作日 **0** 单；工作日 oracle top8/天 56.82%、
  top10/天 55.45%，各置信档 51~54%。
- 结论（表述修正）：oracle 上界只证明**现有 h3/h10 score 信息集内**工作日 60% 不可达，
  不是"任何方法都不可达"——这是两个不同命题，此前"数学边界"措辞过重。换信息源/换方法仍可能提升。

## 8. faiss 重新审查 + 博主 65-70% 现象的定量解释（2026-11-22）

用户质疑：多个币安广场博主长期实时带单 10-20 单/天、63-70%，不像作假；且 faiss 形态
不挑周末、不比 LGBM 差太多，说明还有提升空间。重新审查 faiss 全链路：

**发现并修正一个真 bug**：`tool/faiss_daily_quantile.py:35` 用 `int(ace[i])` 存方向，
但 ace 绝对值 max 0.82（`int()` 对 100% 行 = 0），第 44 行 `np.where(a>0,1,0)` 恒判跌。
故 §46.10 因果实现② 的 52.80% 是"全押跌"的准确率，不是滚动阈值的真实表现。
修正（`tool/faiss_daily_quantile_fixed.py`，保留浮点 ace）后 BTC 51.55%、WD 46.51%——
**未提升**，结论不变。另两个因果实现用原始 ace，无此 bug。

**faiss 信号真实但未突破**：2026 test 按 |ace| 分档方向胜率单调 50.36%→56.17%
（工作日 50.43%→54.99%），确是真实信号；但最高档也只有 56%。oracle top7 工作日 64.21%
的 `|ace|` 最低仅 0.031——那些高胜率 bar 的低 ace 说明其优势来自"当日相对排名"这一前视，
事前不可识别。12pp 缺口是前视定义的产物，不是缺实时数据能补的。

**博主 65-70% 的定量解释（关键）**：详录 §18 已研究过同一参照。用现役 h3 分数压单量即可
复现：全场 top10/天 = 66.98%、top15/天 = 66.94%。但这些高置信单**周末占比 95-97%**，
工作日仅 0.3-0.8 单/天。即"高胜率 + 低单量"靠**更挑单**实现，胜率是单量的函数（§18 跨度 9pp），
那些单天然集中在低波周末。**博主大概率也没做到"工作日 10 单 + 60%"**——这是比其参照更难的
额外约束，不能用"博主 65-70%"论证其可行性。可验证：核对博主逐单时间戳的星期分布。

**净结论**：单量（阈值机制）可解；准确率要突破现有分数需新信息源。但"周末高胜率"用现役信号
压单量即可达成，不必换方法；真正没解的是"工作日高胜率"，且此项现有证据全部指向需新数据。
